# sw-widget（しくみ・つなぎ）の進み具合

SwiftUI 版（native/）で、ウィジェットとアプリ全体のしくみを、いまの版（app/src）と同じにした記録。
✓＝できた／△＝一部（理由つき）／✗＝まだ。

## 1. ウィジェット（3.20・1.12・4.1.7）
- ✓ ウィジェット拡張を native/LukkoWidget に（いまの版の KimatteruWidget.swift・Info.plist・entitlements をそのまま）
- ✓ bundle ID `com.kimatteru.app.widget`・kind `KimatteruWidget`・App Group `group.com.kimatteru.app`・キー `widget` は変えない（置いてあるウィジェットがそのまま動く）
- ✓ project.yml：app-extension、iOS 17、Manual 署名、版とビルド番号は本体と同じ（agvtool -all で両方）、本体に埋め込む。署名なしの CI ビルドも通る
- ✓ codemagic.yaml の native-testflight：本体とウィジェットの両方の署名ファイルを取る（ios-testflight と同じ繰り返し）。use-profiles は両方のターゲットに当たる
- ✓ 渡す中身は Kit の WidgetCore.buildPayload（正解表あり）。App Group に書いて reloadAllTimelines
- ✓ 渡す時：保存の間合い（_flushFile）・背景に回るとき・戻ってきたとき（必ず）・起動のあと。印（予定・数・種類の数・週のはじまり）が同じなら渡さない。「名前を隠す」の切り替えでも渡し直す
- ✓ 押したときの行き先：いまの版にも無い（widgetURL なし。開くだけ）。URL スキームも無いので onOpenURL は不要
- ✓ 診断で見る結果（model.widgetLast・model.sendWidgetNow）を用意。試験では「渡せた」を確かめる

## 3. 引っ越しの安全
- ✓ 元のもの（保存ファイル・localStorage）は、手を付ける前に丸ごと写す。写せなければ保存ファイルを書き換えない（書こうとすると「保存できていません」）
- ✓ localStorage を読めなかったら、長めに待ってもう一度読む
- ✓ ファイルのほうが新しく中身も違うとき：古いほう（localStorage）を「戻す前の控え」に残し、「新しいほうの保存から開きました（古いほうは控えに残しました）」
- ✓ localStorage が消えていてファイルから戻したとき：「保存されていたn件の予定を戻しました」
- ✓ 使えるものが無い・引っ越し後に保存ファイルが読めない：端末の中の控えのほうが新しければ、そこから戻す
- ✓ 書き出しの対応表（lukko.exportMap）を持ってくる。lukko.shield は同じ名前で書く
- ✓ MigrationUITests は緑のまま

## いまの版と違うところ
- 下のタブは iPhone 標準の TabView（「＋」はタブの 5 つ目「追加」）。いまの版は自前の浮いたタブ
- 保存は 1 か所（ファイル）だけ。いまの版の localStorage と照らし合わせる _checkFile は、引っ越しのときに 1 回だけ行う
- ウィジェットの描き直しの印は、いまの版と同じく種類の色を見ない（色だけ変えても次に戻ってきたときまで古い色）

## ほかの担当へ
- 予定の字の倍率は `model.evScale` を使う（core.evScale() だけだと iPhone の文字の大きさが効かない）
- 取り込みの画面で設定アプリを開くときは `model.retryImportOnReturn = true`
- 空いてる日を送った直後に `engine.maybeAskReview("share")`
- 設定のタブを押した回数 `model.settingsTabTaps`（先頭へ戻すのに使える）
- 手ごたえは `haptic("pen")`（penTick）・`haptic("success")`（settleSuccess）も使える
