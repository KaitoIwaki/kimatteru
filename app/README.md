# 決まってる？ — iOSアプリ

不確定な予定と決まっている予定が、カレンダーを開いた瞬間に見分けられるアプリ。
Windows で開発し、iOS のビルドと署名は Codemagic のクラウド Mac で行う（Capacitor）。

**名前は `決まってる？`。合印の `✓？` の、`？` の側を言葉にしたもの。**
マークと名前が同じものを指している——ここは崩さない。

一度 `Ink` → `Penciled In` と英語名に振ったが、戻した。判断を書き残しておく。

- 英語には `pencil it in`（仮で入れておく）／`ink it in`（インクで書く）という、
  塗りと点線とまったく同じ軸の言い回しがある。名前として筋は通っていた
- **しかしアプリはえんぴつもペンも描いていない。** 描いているのは塗りと点線で、
  この比喩は**開発者にしか見えない**。利用者が気づく道筋がどこにもない
- 広がり方はほぼ口コミなのに、「ペンシルドインっていうアプリ」は**言えない**
- 決め手になったはずの検索も、`Penciled In` で日本語検索に当たるわけではない。
  **ASO は1ミリも改善しない**まま、読みやすさとロゴとの一致だけを失っていた
- そもそも `Ink` が埋まっていたあと「空いているもの」で候補を絞ったのが誤りだった。
  `Penciled In` が残ったのは一番良かったからではなく、他が埋まっていたから

検索語は名前そのものではなく **App名の欄**で取る（`決まってる？ 予定とシフトのカレンダー`）。
えんぴつとインクの比喩は捨てず、**説明文の一文**として残してある。

`決まってる`／`まだ不確定` は作成画面の**状態の言葉**（アプリ名とは別物）。

**いまの版：v0.17.0 / TestFlight 配信中 / App Store 未提出**

## いちばん大事な考え方

このアプリが解いているのは「**確定した予定と、入るかもしれない予定が同じ見た目で並ぶ**」問題。

- **色 ＝ 種類**（バイト／用事／遊び／その他）
- **塗り／点線 ＝ 確定度**（決まってる／まだ不確定）

この2軸を壊す変更はしない。迷ったら「月表示を開いた瞬間に伝わるか」で判断する。

見た目のトーンは「**静かな文房具**」。紙のような地に墨色の文字、影は使わず細い罫線。
**色を持つのは予定だけ**で、ボタンやUIには種類の3色を使わない。

| `src/notify.js` | ローカル通知。シフト終了の記録うながし（`worked`）と、予定ごとのお知らせ（`remind`）の2種類 |

### よく触る定数（App.jsx の先頭）

- `FILL_SOFT` … 予定の塗りをどれだけ白に寄せるか（今は `0.32`）
- `HOLIDAY_RED` `SATURDAY_BLUE` … 日曜・祝日と土曜の色
- `MONTH_BAR_H` `MONTH_BAR_FS` … 月表示の帯の高さと文字（今は 15px / 10px）。

## データ

`localStorage` の `kimatteru.v2` に、予定・種類・バイト先・設定・お知らせを保存。

予定は `y`（西暦）・`m`（0始まりの月）・`day` に加えて、

- **`days`** … 何日続くか。無いか1なら1日。2以上だと月表示で列をまたぐ1本の帯になる（`buildWeeks()` が週ごとに段を決める）。**終日の予定にだけ許す**（時間指定を日またぎにすると実働時間と給料の計算が壊れるため）
- **`remindMin`** … 何分前に知らせるか。無ければ知らせない。終日の予定は朝9時が基準。
  10分前〜1週間前（10080）まで。長い側は「7日後」のように日数で文面を作る
- **`breakMin`** … 休憩の分数。無ければ0。実績を記録するダイアログで選ぶ
- **`place`** … 場所。空なら持たせない（`undefined`）。詳細画面で Google マップへのリンクになる。
  住所として解釈できるかは向こうに任せ、こちらでは何も検証しない
- **`memo`** … メモ。持ち物などを書く。改行を含む。空なら持たせない
- **`repId`** … くり返しで作ったときの印。同じ回で作ったものは同じ値を持つ。
  削除の確認で「この日から先もまとめて」を出すためだけに使う

**予定が消えることは、機能がひとつ動かないのとは重さが違う。**
カレンダーアプリの低評価は「予定が突然消えた」がいちばん多い。
サーバーを持たないので、端末から消えたら戻せない。

保存は `store.js` に閉じてある。**二重に書く。**

- `localStorage` … 毎回すぐ書く。起動時に読むのもこちら
- ファイル（`Library/kimatteru-store.json`）… 手が止まって1.2秒後と、
  アプリが背景に回った瞬間に書く。iOS の WKWebView に入っているデータは
  端末の空きが少ないときに OS の判断で消えることがあるが、
  アプリのファイルは消えない。`Library` にしているのは iCloud のバックアップに
  入るため（`Data` は入らない、`Cache` は消される）

起動時に `localStorage` が空でファイルに中身があれば、そこから戻して画面で知らせる。
`localStorage` が生きているときはファイルを見ない（編集中の内容を消さないため）。

**保存に失敗したら、必ず画面に出す。** 以前は黙って諦めていた。
黙っていると、いちばん悪い形で気づくことになる——画面には出ているのに、
閉じて開いたら消えている。

**読み込むときは必ず `sanitizeEvents()` を通す。**
壊れた予定が1件でも混じると描画の途中で落ち、壊れたまま保存されているので
開き直しても同じところで落ちる——アプリを消すまで戻れなくなる
（エラー境界は置いていない）。捨てるのは日付が読めないものだけで、
残りは直して残す。利用者の予定を黙って消すほうが、表示が少し変になるより悪い。
種類は色を引くのに使うので、形が違えば既定に戻す（`typesOk()`）。

**id は必ず `uid()` で作る。** 時刻だけで作ると、端末の時計を戻したときや、
いつか誰かとカレンダーを混ぜるときに、別の予定が同じ id になりうる。
混ぜる側は id で見分けるしかないので、ぶつかると黙って片方が消える。

控えの形は `BACKUP_FORMAT`。中身の並びを変えたら1つ上げる。
古い版は、それより上の控えを読まずに断る（黙って読むと壊れた予定が並ぶ）。

**くり返しは規則として持たず、作るときに予定の実体を並べる。**
1回ごとに確定／未確定・実働時間・時給が違うのがこのアプリの要で、
規則で持つと「今週の土曜だけ休み」が表せない。半年ぶん毎日で183件になるが、
`localStorage` にも描画にも効かない量（`MAX_REPEAT` で200件に止めている）。
- **`updatedAt`** … 最後に書き換えた時刻。いまは使っていないが、
  将来クラウド同期を作るとき「どちらが新しいか」の判定に要る

**時間と金額を出すところは必ず `paidHours()` を通す。**
`hoursBetween()` を直に使うと休憩が引かれず、休憩が時給に入らない
バイト先で金額が多めに出る（6時間勤務・休憩60分で20%多い）。

時計の分は **5分刻みで固定**（`MIN_STEP`）。設定の「時間の刻み幅」は廃止した
（ホイールで選ぶのに粗い刻みは邪魔なだけで、既定の30分だと 17:20 が選べなかった）。

**時給はバイト先ごと**に決める。設定画面の時給入力は廃止した。
`settings.hourly` は、バイト先を選んでいない昔の予定のための控えとして残してある。

## 触り方の決めごと

- **予定を作る画面は、いつも使うものだけ並べる。**
  くり返し・場所・メモは下の「＋」から足す（`draft.added`）。押した順ではなく
  いつも同じ並びで出す。✕ で外すときは値も一緒に捨てる
  （行だけ消えて中身が残ると、保存されて驚く）。
  項目を足すときは、まずここに入るか考える。常設の行を増やすのは、
  「シフトを1件入れたいだけ」の人にスクロールを課すということ
- **空っぽの画面には、次の一手を置く。**
  予定が0件のとき、月表示は「＋」を指す案内を出し、空き状況は取り込みを勧める。
  1件でも入ったら黙る。取り込みを最初の画面で勧めないのは、
  取り込むと全部が実線になり、点線＝このアプリの意味が伝わらないまま
  日常に入るため。許可を求めるのも、何のためか分かってからでいい
- **シェアは、そのものを見ている画面に置く。**
  「空いてる日をシェア」はまとめタブではなく空き状況の画面。
  「今月のまとめカード」はまとめタブ。設定には置かない
  （設定は一度決めて触らない場所で、押すたびに結果が変わるものとは性質が違う）
- **設定の一覧が増えるものは、たたんでおく。**
  予定の種類は増えていく。たたんだ行には色の点と数だけ出す
- **月表示の帯はタップを受けない**（`pointer-events:none`）。細い帯を狙わせず、マスのどこを押してもその日の一覧が開き、そこから選ぶ。日またぎの帯を押したときは、押した位置の下にある日が開く
- **月表示は画面の横いっぱい**。外枠も角丸も付けない。
  曜日の見出しとマスの左右の余白は**必ず同じ**にする（違うと列が横にずれる）
- **前後の月のマスに面を敷かない**。情報がゼロなのに罫線より主張し、
  グリッドの端がギザギザに見える
- **日の一覧は左スワイプで削除**（ゴミ箱アイコン）。消す前に必ず確認ダイアログを通す
- **お知らせは一覧に全文を出さない**。行は種類（シフトの記録／アップデート）と表題だけで、
  タップすると画面中央に開いて全文と日付が出る
- **予定を作る画面は既定で全部たたむ**。開けるのは一度に一つ（`draft.picking` が持ち主）。確定／不確定だけは、このアプリの核なのでたたまない
- **色を変えるのは設定の「種類」だけ**。作成画面には置かない。
  種類の名前の変更と追加も設定から行う（自分で足した種類は、名前を変えると
  「未確定の◯◯」という言い回しも作り直す。最初からある4つは触らない）
- **書き出す PNG と同じ見た目のカード**（まとめ・空きシェア）は、中の文字も
  固定色にする。テーマ変数を使うとダークモードで白地に白文字になる

**端末の中だけ**で、外部には一切送らない。端末間の同期はない。
その代わり **設定 →「控え」** から全データを JSON で書き出し／読み込みできる
（規約に「控えを取ってください」と書いてある以上、取る手段は要る）。

**戻すのは、ファイルをそのままえらばせる。**
「控えを開いて、全文をコピーして、アプリに戻って貼る」は、書き出した本人でも手が止まる。
`input[type=file]` は WKWebView からでもファイルアプリを開けるので、
これだけのためにプラグインは足さない（足すと iOS 側の同期も要る）。
**貼り付けは逃げ道として残す。** えらべなかった人が行き止まりになるほうが悪い。
読んだあとは `input.value` を空に戻す——同じファイルをもう一度えらんでも
`change` が起きないと、一度断られた人が二度目を試せない。

**取り返しのつかない操作は、済んだことを言う。**
控えから戻すと予定が丸ごと置き換わるので、終わったら知らせを出す
（`v.toastShown`）。知らせはまとめ／空きシェアの画面の中だけに置かない。
戻したあとは月表示に移るので、そこに無いと無言で全部入れ替わったように見える。

## 検証のしかた（重要）

スクリーンショット生成に html2canvas を使うと、
**アニメーション中の要素・transform・重なりを正しく描けない**。
過去にこれを「描画ツールの制約」と誤判断して、実機に崩れたまま出してしまったことがある。
確認ダイアログの1枚が長らく撮れなかったのもこれが理由。
**いまは `tools/make-shots.mjs` が本物のブラウザで撮るので、重なりもぼかしも出る。**

**レイアウトは必ず実寸で確かめる。**

```js
// 例：要素の幅・位置・重なりを測る
el.getBoundingClientRect()
// 例：文字が省略されているか
body.scrollWidth > body.clientWidth
```

また確認用ペインは `document.hidden === true` のため、
`requestAnimationFrame` が動かず `setTimeout` も1秒に制限される。
タイマー絡みの検証では待ち時間を長め（2秒以上）に取る。

```bash

```
`src/docs.js` から公開用の `legal/*.html` を書き出す。push すると GitHub Pages に反映される。


```bash

npm i -D playwright && npx playwright install chromium
node tools/make-shots.mjs
```
App Store 用のスクリーンショットを撮り直す（6.9インチ・1290×2796）。
`store-assets/screenshots-6.9/` に8枚書き出す。予定は `?demo=1` のサンプル。

**playwright は `package.json` に入れていない。** postinstall がブラウザ本体
（150MBほど）を落としに行くので、常設すると Codemagic のビルドが重くなる。
撮るときだけ入れて、済んだら消してよい。

```bash
node tools/make-demo-backup.mjs           # 今月ぶん
node tools/make-demo-backup.mjs 2026-09   # 月を指定
```
**実機で撮るための**サンプル予定を、控えの形で `store-assets/` に書き出す。
`?demo=1` はブラウザ用で、インストールした本物のアプリでは効かないため。

できた JSON を iPhone に送り（AirDrop・メール添付・iCloud Drive など）、
アプリの **設定 →「控えから戻す」→ ファイルをえらぶ**で入る。

> ⚠ **復元は置き換えなので、その端末の予定は消える。**
> 自分の予定が入っている端末で使うなら、先に「控えを書き出す」で退避しておくこと。

20件で、働いた記録・決まってる・まだ・流れた の4つがそろうように置いてある。
バイト先を2つ（掛け持ち）、休憩つきの実績、日をまたぐ終日の帯、場所とメモ、
希望シフトの時間まで含めてあるので、どの画面を撮っても中身が入っている。

## 課金の方針

`monetization-plan.md` 参照。原則は **「記録するのは無料。判断を助けるのが有料」**。

看板（確定度カレンダー）と記録まわりは永久無料。
Pro の芯は **未確定を含んだ見通し**（`72,000〜88,000円` のような幅、
目標からの逆算、年収の壁）。**確定度を持っているアプリにしか作れない**ので、
看板が無料で強いほど Pro の価値が上がる関係になっている。

深夜手当・残業割増・休憩控除は Pro ではなく**正しさの問題**として無料寄りに置く
（無いと金額が「簡易」ではなく間違いになるため）。

実装はまだ入れていない（まず無料で公開して、誰が来るかを見る段階）。

## 既知の未対応

- 端末間のデータ同期（控えの書き出し／読み込みで代替している）
- 深夜手当・残業割増などの時間帯別時給、**休憩時間の控除**（`monetization-plan.md` 参照）
- 候補日を相手に送って回答してもらう共有リンク
- 月表示の予定名は確定6文字・未確定5文字まで。それ以上は切れる
- 日をまたげるのは**終日の予定だけ**（時間指定は1日で完結する決め）
