# 決まってる？ — iOSアプリ

不確定な予定と決まっている予定が、カレンダーを開いた瞬間に見分けられるアプリ。
Windows で開発し、iOS のビルドと署名は Codemagic のクラウド Mac で行う（Capacitor）。

**いまの版：v0.14.0 / TestFlight 配信中 / App Store 未提出**

---

## いちばん大事な考え方

このアプリが解いているのは「**確定した予定と、入るかもしれない予定が同じ見た目で並ぶ**」問題。

- **色 ＝ 種類**（バイト／用事／遊び／その他）
- **塗り／点線 ＝ 確定度**（決まってる／まだ不確定）

この2軸を壊す変更はしない。迷ったら「月表示を開いた瞬間に伝わるか」で判断する。

見た目のトーンは「**静かな文房具**」。紙のような地に墨色の文字、影は使わず細い罫線。
**色を持つのは予定だけ**で、ボタンやUIには種類の3色を使わない。

## 動かす

```bash
npm --prefix app run dev
```

同じ Wi-Fi の iPhone からは、表示される Network のアドレスで開ける。
`?demo=1` を付けるとサンプルの予定入り、`?import=1` で取り込み画面をPCでも確認できる。

触覚・OS通知・共有シート・カレンダー取り込みはブラウザでは動かない（実機のみ）。

## 構成

| ファイル | 役割 |
|---|---|
| `src/App.jsx` | 状態と表示ロジック。`renderVals()` が画面に渡す値 `v` を全部組み立てる |
| `src/view.jsx` | 見た目。`v` を受け取って JSX を返すだけ。ロジックを持たない |
| `src/style.js` | CSS文字列 → React の style オブジェクト変換 |
| `src/styles.css` | 色の変数、キーフレーム、セーフエリア、アイランド型ナビ |
| `src/holidays.js` | 日本の祝日を計算（通信なし。振替休日・国民の休日・春分/秋分に対応） |
| `src/notices.js` | ベルに溜まるお知らせ。`RELEASE_NOTES` に足すと更新案内が出る |
| `src/calendarimport.js` | iPhone のカレンダーから読み込む。祝日カレンダーは除外 |
| `src/notify.js` | ローカル通知。シフト終了の記録うながし（`worked`）と、予定ごとのお知らせ（`remind`）の2種類 |
| `src/haptics.js` `src/statusbar.js` | 触覚とステータスバー。ネイティブ以外では自動的に無効 |
| `src/sharecard.js` `src/shareimg.js` | シェア画像をキャンバスに直接描いて共有シートへ |
| `src/docs.js` | 規約とプライバシーポリシーの原稿（アプリ内と公開HTMLで共用） |
| `src/demo.js` | `?demo=1` のときだけ使うサンプル |

**直す場所**：見た目は `view.jsx`、挙動や計算は `App.jsx`。

### よく触る定数（App.jsx の先頭）

- `FILL_SOFT` … 予定の塗りをどれだけ白に寄せるか（今は `0.32`）
- `HOLIDAY_RED` `SATURDAY_BLUE` … 日曜・祝日と土曜の色
- `MONTH_BAR_H` `MONTH_BAR_FS` … 月表示の帯の高さと文字（今は 15px / 10px）。
  ここを変えると段の高さ（`MONTH_LANE_H`）と週の高さも一緒に付いてくる

## データ

`localStorage` の `kimatteru.v2` に、予定・種類・バイト先・設定・お知らせを保存。

予定は `y`（西暦）・`m`（0始まりの月）・`day` に加えて、

- **`days`** … 何日続くか。無いか1なら1日。2以上だと月表示で列をまたぐ1本の帯になる（`buildWeeks()` が週ごとに段を決める）。**終日の予定にだけ許す**（時間指定を日またぎにすると実働時間と給料の計算が壊れるため）
- **`remindMin`** … 何分前に知らせるか。無ければ知らせない。終日の予定は朝9時が基準。
  10分前〜1週間前（10080）まで。長い側は「7日後」のように日数で文面を作る
- **`breakMin`** … 休憩の分数。無ければ0。実績を記録するダイアログで選ぶ
- **`place`** … 場所。空なら持たせない（`undefined`）。詳細画面で Google マップへのリンクになる。
  住所として解釈できるかは向こうに任せ、こちらでは何も検証しない
- **`memo`** … メモ。持ち物などを書く。改行を含む。空なら持たせない
- **`repId`** … くり返しで作ったときの印。同じ回で作ったものは同じ値を持つ。
  削除の確認で「この日から先もまとめて」を出すためだけに使う

**id は必ず `uid()` で作る。** 時刻だけで作ると、端末の時計を戻したときや、
いつか誰かとカレンダーを混ぜるときに、別の予定が同じ id になりうる。
混ぜる側は id で見分けるしかないので、ぶつかると黙って片方が消える。

控えの形は `BACKUP_FORMAT`。中身の並びを変えたら1つ上げる。
古い版は、それより上の控えを読まずに断る（黙って読むと壊れた予定が並ぶ）。

**くり返しは規則として持たず、作るときに予定の実体を並べる。**
1回ごとに確定／未確定・実働時間・時給が違うのがこのアプリの要で、
規則で持つと「今週の土曜だけ休み」が表せない。半年ぶん毎日で183件になるが、
`localStorage` にも描画にも効かない量（`MAX_REPEAT` で200件に止めている）。
- **`updatedAt`** … 最後に書き換えた時刻。いまは使っていないが、
  将来クラウド同期を作るとき「どちらが新しいか」の判定に要る

**時間と金額を出すところは必ず `paidHours()` を通す。**
`hoursBetween()` を直に使うと休憩が引かれず、休憩が時給に入らない
バイト先で金額が多めに出る（6時間勤務・休憩60分で20%多い）。

時計の分は **5分刻みで固定**（`MIN_STEP`）。設定の「時間の刻み幅」は廃止した
（ホイールで選ぶのに粗い刻みは邪魔なだけで、既定の30分だと 17:20 が選べなかった）。

**時給はバイト先ごと**に決める。設定画面の時給入力は廃止した。
`settings.hourly` は、バイト先を選んでいない昔の予定のための控えとして残してある。

## 触り方の決めごと

- **月表示の帯はタップを受けない**（`pointer-events:none`）。細い帯を狙わせず、マスのどこを押してもその日の一覧が開き、そこから選ぶ。日またぎの帯を押したときは、押した位置の下にある日が開く
- **月表示は画面の横いっぱい**。外枠も角丸も付けない。
  曜日の見出しとマスの左右の余白は**必ず同じ**にする（違うと列が横にずれる）
- **前後の月のマスに面を敷かない**。情報がゼロなのに罫線より主張し、
  グリッドの端がギザギザに見える
- **日の一覧は左スワイプで削除**（ゴミ箱アイコン）。消す前に必ず確認ダイアログを通す
- **お知らせは一覧に全文を出さない**。行は種類（シフトの記録／アップデート）と表題だけで、
  タップすると画面中央に開いて全文と日付が出る
- **予定を作る画面は既定で全部たたむ**。開けるのは一度に一つ（`draft.picking` が持ち主）。確定／不確定だけは、このアプリの核なのでたたまない
- **色を変えるのは設定の「種類」だけ**。作成画面には置かない。
  種類の名前の変更と追加も設定から行う（自分で足した種類は、名前を変えると
  「未確定の◯◯」という言い回しも作り直す。最初からある4つは触らない）
- **書き出す PNG と同じ見た目のカード**（まとめ・空きシェア）は、中の文字も
  固定色にする。テーマ変数を使うとダークモードで白地に白文字になる

**端末の中だけ**で、外部には一切送らない。端末間の同期はない。
その代わり **設定 →「控え」** から全データを JSON で書き出し／読み込みできる
（規約に「控えを取ってください」と書いてある以上、取る手段は要る）。

## 検証のしかた（重要）

この環境ではスクリーンショット生成（html2canvas）が
**アニメーション中の要素・transform・重なりを正しく描けない**。
過去にこれを「描画ツールの制約」と誤判断して、実機に崩れたまま出してしまったことがある。

**レイアウトは必ず実寸で確かめる。**

```js
// 例：要素の幅・位置・重なりを測る
el.getBoundingClientRect()
// 例：文字が省略されているか
body.scrollWidth > body.clientWidth
```

また確認用ペインは `document.hidden === true` のため、
`requestAnimationFrame` が動かず `setTimeout` も1秒に制限される。
タイマー絡みの検証では待ち時間を長め（2秒以上）に取る。

## 課金の方針

`monetization-plan.md` 参照。原則は **「記録するのは無料。判断を助けるのが有料」**。

看板（確定度カレンダー）と記録まわりは永久無料。
Pro の芯は **未確定を含んだ見通し**（`72,000〜88,000円` のような幅、
目標からの逆算、年収の壁）。**確定度を持っているアプリにしか作れない**ので、
看板が無料で強いほど Pro の価値が上がる関係になっている。

深夜手当・残業割増・休憩控除は Pro ではなく**正しさの問題**として無料寄りに置く
（無いと金額が「簡易」ではなく間違いになるため）。

実装はまだ入れていない（まず無料で公開して、誰が来るかを見る段階）。

## 既知の未対応

- 端末間のデータ同期（控えの書き出し／読み込みで代替している）
- 深夜手当・残業割増などの時間帯別時給、**休憩時間の控除**（`monetization-plan.md` 参照）
- 候補日を相手に送って回答してもらう共有リンク
- 月表示の予定名は確定6文字・未確定5文字まで。それ以上は切れる
- 日をまたげるのは**終日の予定だけ**（時間指定は1日で完結する決め）
